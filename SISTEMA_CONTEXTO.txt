1. DESCRIPCIÓN GENERAL
--------------------------------------------------------------------------------
Sistema web interno de SEDUC (Servicios de Educación).
Nombre: "Seduc Hub – Portal Operativo"
URL QA:  qa.seduc.cl/jorquera/sistema_panel_qa/
Tipo:    Portal intranet para funcionarios. PHP + MySQL. Sin framework.

El sistema sirve como punto central de acceso a:
  - Información personal del funcionario (liquidaciones, documentos, perfil)
  - Beneficios y convenios institucionales
  - Comunicación interna (seduc informa, cápsulas de ciberseguridad)
  - Agenda y calendario de eventos institucionales
  - Accesos rápidos a otras aplicaciones (apps)

TABLAS ACTIVAS EN PRODUCCIÓN
================================================

────────────────────────────────────────────────
TABLA: menu_h
────────────────────────────────────────────────
Propósito: Define dinámicamente los ítems del menú de navegación principal.
           Cada fila = un ítem del topbar. Al agregar una fila aquí, aparece
           automáticamente en el menú de todas las páginas.

Columnas:
  id_menu_h          INT  PK AUTO_INCREMENT
  menu               VARCHAR  — Texto a mostrar en el menú (ej: "Inicio", "eventos")
  pagina             VARCHAR  — Archivo PHP destino (ej: "index_1.php", "eventos.php")
  carpeta            VARCHAR  — Subcarpeta si aplica (normalmente vacío)
  icono              VARCHAR  — (reservado, no usado actualmente)
  orden              INT      — Orden de aparición en el menú (ASC)
  final              VARCHAR  — "no" por defecto
  activo             TINYINT  — 1 = visible, 0 = oculto
  fecha_creacion     DATETIME
  fecha_actualizacion DATETIME

Datos actuales (8 filas):
  1 Inicio        → index_1.php      orden 1
  2 Apps          → apps.php         orden 2
  3 Contactos     → contactos.php    orden 3
  4 Notas         → notas.php        orden 4
  5 Beneficios    → beneficio.php    orden 5
  6 seduc Informa → seduc_informa.php orden 6
  7 Informativo   → capsulas.php     orden 7
  8 eventos       → eventos.php      orden 8
  (Recursos se agrega automático por código como ítem fijo, orden 999)

Archivos que la usan:
  componentes/menu_cabecera.php → función menus_cabezera($conn)

IMPORTANTE: La columna "pagina" es la fuente de verdad del href del menú.
No existe mapeo hardcodeado; si se agrega fila a esta tabla, aparece solo.

────────────────────────────────────────────────
TABLA: usuarios
────────────────────────────────────────────────
Propósito: Autenticación y datos de perfil de los usuarios del panel.

Columnas:
  id                 INT PK AUTO_INCREMENT
  nombre             VARCHAR
  apellido_paterno   VARCHAR
  apellido_materno   VARCHAR
  email              VARCHAR  — usado como login (único)
  clave              VARCHAR  — hash de contraseña
  cargo              VARCHAR  — ej: "Analista Programador"
  intentos_fallidos  INT      — bloqueo tras 3 intentos fallidos
  estado             TINYINT  — 1 = activo
  foto               VARCHAR  — ruta relativa a imagen de perfil

Archivos que la usan:
  validar.php          → SELECT por email, UPDATE intentos_fallidos
  componentes/auth.php → función iniciarSesionPanel()
  componentes/rail_acciones.php → obtenerUsuariosCalendario() (busca en "usuario"
                                  o "usuarios", nombre flexible)

────────────────────────────────────────────────
TABLA: contenedor
────────────────────────────────────────────────
Propósito: Accesos directos / apps que aparecen en el dashboard (index_1.php).
           Cada fila es una tarjeta con ícono, nombre y URL.

Columnas:
  id          INT PK AUTO_INCREMENT
  nombre      VARCHAR(150) — Nombre del acceso (ej: "SGP", "Google Drive")
  url_        VARCHAR(255) — URL de destino
  imagen      VARCHAR      — Nombre de archivo en carpeta /imagenes/

Archivos que la usan:
  index_1.php → SELECT id, nombre, url_, imagen WHERE id_usuario = 1

────────────────────────────────────────────────
TABLA: convenios
────────────────────────────────────────────────
Propósito: Convenios y beneficios disponibles para funcionarios.
           Se muestran en beneficio.php y se administran en admin_convenios.php.

Columnas:
  id_convenio    INT PK AUTO_INCREMENT
  id_tipo        INT  FK → tipo_convenio.id_tipo
  empresa        VARCHAR  — Nombre de la empresa/proveedor
  descripcion    TEXT     — Descripción del beneficio
  descuento      VARCHAR  — Ej: "20%", "precio preferencial"
  imagen         VARCHAR  — Nombre de archivo en carpeta /imagenes/
  url            VARCHAR  — Sitio web del convenio
  fecha_inicio   DATE
  fecha_termino  DATE
  activo         TINYINT(1)  — 1 = visible en beneficio.php
  destacado      TINYINT(1)  — 1 = aparece primero (ORDER BY destacado DESC)

Archivos que la usan:
  beneficio.php        → SELECT con LEFT JOIN tipo_convenio, filtro por id_tipo
  admin_convenios.php  → SELECT, INSERT, UPDATE, DELETE completo (CRUD)

────────────────────────────────────────────────
TABLA: tipo_convenio
────────────────────────────────────────────────
Propósito: Categorías de convenios para filtrar en beneficio.php.

Columnas:
  id_tipo    INT PK AUTO_INCREMENT
  nombre     VARCHAR  — Nombre de la categoría (ej: "Salud", "Educación")
  icono      VARCHAR  — Emoji o código de ícono
  orden      INT      — Orden de aparición

Relación: 1 tipo_convenio → N convenios (FK convenios.id_tipo)

Archivos que la usan:
  beneficio.php        → SELECT para poblar filtros
  admin_convenios.php  → SELECT para desplegable de tipo en formulario

6. MENÚ DE CABECERA — FUNCIONAMIENTO
--------------------------------------------------------------------------------
La función menus_cabezera($conn) en componentes/menu_cabecera.php
hace SELECT a la tabla menu_h y devuelve array de [menu, href, orden].

La función construirHrefMenuCabecera() usa directamente el campo "pagina"
de la BD como href — sin mapeo hardcodeado. La BD es la fuente de verdad.

Se agrega automáticamente "Recursos" (recursos.php) si no está en la BD.

El dropdown de usuario (renderTopbarUserMenu()) muestra:
  1. Perfil          → perfil.php
  2. Liquidaciones   → liquidaciones.php
  3. Documentos      → documentos.php
  4. Cerrar sesión   → logout.php  (rojo, peligro)

7. CONVENCIONES Y PATRONES DE CÓDIGO
--------------------------------------------------------------------------------
- Cada página PHP carga su CSS inline en <style> dentro del <head>
- No hay framework CSS externo (no Bootstrap, no Tailwind). CSS propio.
- Fuentes: "DM Sans" (cuerpo) y "Fraunces" (títulos) desde Google Fonts
- Paleta principal: --primary #2f57b7 / --navy #1a2744 / --accent #f0a500
- Todas las páginas siguen el mismo patrón de cabecera:
    require_once __DIR__ . '/class/conexion.php';
    require_once __DIR__ . '/componentes/menu_cabecera.php';
    $db = new Conexion(); $conn = $db->getConexion();
    $menusCabecera = menus_cabezera($conn);
    $paginaActual  = basename($_SERVER['PHP_SELF'] ?? 'pagina.php');
    $db->cerrar();
  Luego en el HTML:
    <header class="topbar"> ... menú dinámico + renderTopbarUserMenu() ... </header>
- Imágenes de convenios/apps en carpeta /imagenes/
- Sin ORM. Queries directas con MySQLi (prepared statements en validar.php,
  strings interpoladas en el resto)
